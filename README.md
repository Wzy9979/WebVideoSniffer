# 网页视频嗅探器

输入一个网页地址 → 自动嗅探页面里的视频 → **多线程下载** → 自动转成 **MP4** → **文件名保留原视频标题**。

三种嗅探方式，从轻到重，覆盖从静态网页到 JS 重站点的全部情况：

| 方式 | 原理 | 适用 |
|---|---|---|
| **嗅探** | 看服务器返回的 HTML | 直链站、课程站、自建站 |
| **浏览器嗅探** | 开一个真浏览器把页面跑起来，问它到底在播什么 | 抖音这类 JS 站点（HTML 里根本没有地址） |
| **yt-dlp 下载** | 交给 yt-dlp 的站点提取器 | YouTube、B 站等有专门支持的站 |

图形界面（tkinter），**只用 Python 标准库**，没有 pip 依赖。

---

## 一、运行

双击 **`run.bat`**。或者命令行 `python app.py`。

### 前置条件

| 需要 | 作用 | 不装的后果 |
|---|---|---|
| Python 3.10+ | 跑界面（tkinter，标准库自带） | 没法运行 |
| **ffmpeg** | 转 MP4、拉 `.m3u8`、合并音视频 | 下载后不转 MP4；`.m3u8` 下不了 |
| Edge 或 Chrome | 「浏览器嗅探」要用它 | 那个按钮不能用（其余功能照常） |
| yt-dlp（可选） | 抓 YouTube / B 站这类站 | 「yt-dlp 下载」按钮不可用 |

```
winget install Gyan.FFmpeg
pip install -U yt-dlp
```

> **yt-dlp 为什么推荐 pip**：本机实测 `winget install yt-dlp.yt-dlp` 会装到
> `%LOCALAPPDATA%\Microsoft\WinGet\Links`，那个目录**不在 PATH 里**，程序找不到。
> `pip install -U yt-dlp` 装到 Python 的 `Scripts` 目录，那个目录本来就在 PATH 上。

装完**重开**程序。启动时日志会告诉你 ffmpeg / yt-dlp 找到没有。

## 二、怎么用

1. 上面填**网页地址**（视频地址也认），点「嗅探」或直接回车；
2. 中间列出嗅探到的视频，选一个或多个，双击某一行可直接下载；
3. 「保存为」已自动填好标题，想改就改；
4. 选好「下载线程」数；
5. 点「下载选中」；
6. 下完自动转 MP4，文件在 **`downloads\`**；双击任务行可直接打开文件。

**嗅探到 0 个视频**（抖音、YouTube 这类）→ 点 **「浏览器嗅探」**；
还是不行 → 点 **「yt-dlp 下载」**。

### 右上角 Cookie 相关

只有走 yt-dlp 时才起作用。遇到「需要登录」「确认你不是机器人」
「Fresh cookies are needed」这类提示就需要它：

| 方式 | 说明 |
|---|---|
| 下拉框选浏览器 | `--cookies-from-browser`。方便，但 **Chrome/Edge 127+ 之后经常失败**，报 `Failed to decrypt with DPAPI`（yt-dlp 已知问题 [#10927](https://github.com/yt-dlp/yt-dlp/issues/10927)，换最新版也无解） |
| 「Cookie 文件…」按钮 | 读手动导出的 `cookies.txt`（`--cookies`）。**绕开解密，最可靠** |

导出办法：浏览器装 **Get cookies.txt LOCALLY** 扩展 → 在目标网站页面导出 →
回程序点「Cookie 文件…」选中它。

> `cookies.txt` 等同于你的登录凭证，**别外传、别提交 Git**。
> 程序只把它交给本机的 yt-dlp，不会上传到任何地方。

## 三、浏览器嗅探（模拟真人访问）

这是对付抖音这类站点的正解。

### 为什么需要它

实测 `https://v.douyin.com/xxxx/` 这类链接：页面 HTML 有 **72 KB，
里面一个视频地址都没有，连一条 http 链接都没有** —— 地址是 JS 跑起来之后
另外调接口拿的。所以**静态嗅探不可能**找到它，这不是 bug。

### 它是怎么做的

程序启动一个**真实的 Edge/Chrome**（默认无头），像一个真人那样打开页面、
让 JS 跑完、让视频真的播起来，然后：

1. **问 DOM「你在播什么」** —— 读 `document.title` 和 `<video>` 信息；
2. **看网络层** —— 从 CDP 抓 `Network.*` 事件，收下所有媒体响应；
3. **问服务器真实大小** —— 对每个候选发一次 1 字节的 `Range` 请求拿真实体积；
   这一步很关键，因为浏览器只缓冲开头一小段（实测 35 MB 的视频只传了约 700 KB），
   光看"传输了多少"会把大小估错几十倍，排序就乱了；
4. **按体积排序** —— 真正的视频 35.6 MB，音频轨 12.3 MB，
   而页面里那个装饰性小视频只有 194.5 KB。按体积排，主视频稳稳排第一；
5. **音视频分流就合并** —— DASH 站点（抖音就是）把画面和声音拆成**两条流**分别下，
   播放器再实时合起来。只下画面那条，出来的 MP4 就是**哑的**。
   程序识别出这种情况后会把声音轨也下了，再用 ffmpeg 合成一个完整 MP4
   （`-map 0:v:0 -map 1:a:0 -c copy`，无损）。

拿到地址之后**下载仍然是我们自己下的**（第三段那套多线程 + 转 MP4），
所以**不需要碰任何 Cookie 解密** —— 实测抖音连 Cookie 都不用带，
浏览器的作用只是"把真实地址问出来"。

### 实测结果（抖音）

```
静态嗅探        → 0 个地址（如预期）
浏览器嗅探      → 3 个地址：视频轨 35.6 MB / 音频轨 12.3 MB / UI 小素材 194.5 KB
点下载          → 自动补下声音轨并合并
产出            → 48.1 MB，时长 531.3 秒，h264 + aac，文件名是真实标题
```

### 需要登录 / 过验证码怎么办

勾上 **「浏览器嗅探时显示窗口」**，程序会把浏览器窗口显示出来，
你可以手动登录或过验证码。登录状态保存在程序目录的 `browser_profile\`
里，下次不用再来一遍。

## 四、多线程下载

「下载线程」可设 **1 / 2 / 4 / 8 / 16 / 32**，默认 **8**：

| 路径 | 多线程怎么生效 |
|---|---|
| 直链视频 | 用 HTTP `Range` 把**一个文件切成 N 段并发下**，各线程往同一文件的**不同偏移**直接写 |
| yt-dlp 兜底 | 加 `--concurrent-fragments N` |
| HLS（`.m3u8`） | 交给 ffmpeg 拉流，线程数不参与 |

另外**多个视频会同时下载**（2 个任务并行）——「单文件多线程」和「多文件一起下」是两件事，两个都有。

### 安全退化（重要）

分段判断错了会直接产出**坏文件**，所以每一层都退守：

- 先用 `Range: bytes=0-0` **探测**（不用 HEAD，很多服务器拿 405 拒掉）；
  回 `206` 才算支持，回 `200` 说明服务器把整份塞回来了 → **退回单线程**；
- 有的服务器**探测时回 206、真要分段时又回 200** —— 下载途中立刻识别，退回单线程重下；
- 文件小于 **2 MB** 不分段；
- 下完**校验大小**必须等于 `Content-Length`，少一个字节都不当成功；
- 请求带 `Accept-Encoding: identity` —— 服务器一压缩，字节偏移就对不上文件偏移了。

> 多线程**不是万能的**：服务器不限速时，8 线程和 1 线程差不多；
> 真正提速的是「服务器限制单条连接速度」的场景。线程开太大也可能被限流。

## 五、静态嗅探能抓到什么

**能**：`<video src>`、`<video><source src>`、`<audio src>`、直链 `<a href="xxx.mp4">`、
`<meta property="og:video">`、`twitter:player:stream`、JSON-LD 和内联 `<script>`
里的地址（含 `https:\/\/` 转义写法）、正文里裸露的地址（含协议相对和相对路径）。

**故意不收**：正文里裸的 `.ts` / `.m4s` 分片。单独下一个分片没意义，
而且 `.ts` 会把 TypeScript 文件误判成视频。

## 六、转 MP4 是怎么做的

ffmpeg 能把**几乎任何**编码塞进 MP4（连 PCM、DTS 都写得进去），但播放器放不出来。
所以不看「ffmpeg 有没有报错」，而是按**编码白名单**判断：

| 级别 | 做法 | 场景 |
|---|---|---|
| 1 | `-c copy` 无损重封装 | MKV(H.264+AAC) → MP4，**秒级**，画质零损失 |
| 2 | `-c:v copy -c:a aac` 只转音频 | MKV+DTS/FLAC/PCM，几秒，视频不动 |
| 3 | `libx264 + aac` 整体重编码 | 视频编码 MP4 放不了（MPEG-2、VP8） |

每一级做完都用 ffprobe 回头验产出编码，**放不了就自动降级**，
所以到手的 MP4 一定能播。最后统一 `-movflags +faststart`。

### HLS 的清晰度

ffmpeg 拿到**主播放列表**只取第一个变体，而主列表常把低清排前面 ——
实测某个流有 1080p，ffmpeg 却只下 720p。所以程序自己解析主列表，
**挑清晰度最高的变体**（日志会写「已挑最高清晰度 1920x1080」）。

例外：主列表带**独立音频轨**（`#EXT-X-MEDIA:TYPE=AUDIO`）时不挑，原样交给 ffmpeg
—— 那种情况单挑视频变体会把音轨丢掉。

## 七、已知限制

- **静态嗅探不执行 JS** —— 大站用「浏览器嗅探」；
- **标题**：优先 `og:title`，其次 `<title>`，浏览器嗅探用 `document.title`。
  不做猜测性裁剪（`视频标题 - 某某网校` 的后缀会留着），因为「第1讲 - 入门」
  这种正经标题也含 ` - `，误删比留着噪音更糟。想干净自己改「保存为」。
- **不做断点续传**，失败重试是**从头重下**；
- **浏览器嗅探**：无头模式可能被个别站点识别；用「显示浏览器窗口」通常能绕过。
  首次嗅探一个站点要等 10~30 秒（等页面把视频跑起来）。
- 不支持 `blob:` / `data:` 源，不支持 DRM 加密视频；
- 直播流（缺 `#EXT-X-ENDLIST`）会一直下，需要手动「取消选中任务」。

```
python sniffer.py
```

## 九、常见问题

**「yt-dlp 下载」失败了**
不会只给你一句「下载失败」—— yt-dlp 的**原始报错会原样打进日志**：

| 日志里出现 | 原因 | 怎么办 |
|---|---|---|
| `Sign in to confirm you're not a bot` / `login required` | 需要登录 | 右上角 Cookie 选浏览器，或用 Cookie 文件 |
| `Fresh cookies ... are needed` | 需要新鲜 Cookie | 同上；或改用「浏览器嗅探」 |
| `Failed to decrypt with DPAPI` | Chrome/Edge 新版 Cookie 加密 | 改用「Cookie 文件…」（见上文） |
| `This video is unavailable` | 视频删了或非公开 | 换一个 |
| `Unsupported URL` | yt-dlp 不支持这个站 | 用「浏览器嗅探」试试 |

**YouTube 的 JS 运行时**：yt-dlp 新版解 YouTube 需要 JavaScript 运行时，且**默认只认 deno**。
程序检测到系统里有 `node` 会自动加 `--js-runtimes node`，所以**装了 Node.js 就够了**。

**浏览器嗅探抓不到地址**
勾上「显示浏览器窗口」看看页面是不是要求登录/过验证码，手动过一下即可
（登录状态会存在 `browser_profile\`）。

**转出来的 MP4 没声音**
不会发生 —— 音频编码不在白名单时会自动转 AAC；音视频分流的站点会自动合并声音轨。
真遇到了请把日志贴出来。

**多线程开了没用 / 更慢了**
说明这个服务器不限单连接速度，或线程太多被限流。调回 1~4 试试。
